# research/

Tools that dump and inspect the game: cvar and command lists per mod, location files of downloaded maps, decompiled functions of closed mod binaries. Only the scripts are in version control; everything they write stays local.

All Python tools are standard library only and read the game paths from `settings.conf` (written by `deploy.sh`).

## dumps/

Cvar and command dumps per mod, diffs against legacy and against the profile. Details, columns and caveats: `dumps/README.md` (generated by `build_docs.py`, exists after its first run).

- `dump_cvars.py [mod ...]`: starts the 32-bit client (`GAME_BIN_I386`, `GAME_BIN` if that is not set, so every mod runs on the same engine build; its `fs_basepath` is read from the dedicated server next to it) per mod on `fueldump` in a temporary `fs_homepath` that holds only the mod's newest original pk3 (legacy: the pk3 of that client's version) and its `qagame.mp.i386.so` server module, runs `cvarlist`/`cmdlist` over stdin and writes `dumps/<mod>_<version>/{console.log,cvars.tsv,cmds.tsv,modules.tsv}`. Mods without that module are skipped, a crashed run writes no data, and a final report lists dumped, skipped and failed mods per mod. `--list` prints the chosen pk3 and binary per mod without starting the game, `--parse <dir>` re-parses a `console.log` without starting the game. etpro is known to be incompatible with ET: Legacy: its cgame segfaults during map load, so its run always ends in the failed list and no dump is written.
- `build_docs.py`: writes `dumps/<mod>_<version>/diff_legacy.md` (differences to legacy) and `dumps/README.md`.
- `diff_profile.py`: writes `dumps/<mod>_<version>/diff_profile.md` (cvars the profile's exec chain sets that the mod lacks) and `dumps/profile_unused.md`.

Order: `dump_cvars.py`, `build_docs.py`, `diff_profile.py`; the newest folder per mod is used.

Requirements: Python 3.9+, standard library only; the scripts run from any working directory (paths come from the script location and `settings.conf`). `dump_cvars.py` needs the display and writes to a temporary folder, so it runs outside the sandbox. `dump_cvars.py` and `diff_profile.py` need `ETLEGACY_SRC` in `settings.conf` (asked by `deploy.sh`) or the environment to tell client from server engine cvars. `build_docs.py` needs no source.

## locations/

`locations.py` (driven by the `locations` skill; usage in its docstring): `extract` snapshots the location files (`*_loc.dat`, `*_loc_override.dat`) of the pk3s in `<fs_homepath>/etmain/dlcache` into `locations/maps_<YYYY-MM-DD>/` and writes `locations/report_<YYYY-MM-DD>.txt` with new and changed files against the previous snapshot and the snapshot's maps without a file in `<profile>/maps/`. `diff`, `add`, `merge` and `caps` bring them into `<profile>/maps/` (header, Title Case names, maxChars, date and editor). Rerun after new downloads.

## decompile/

`decompile.sh <binary> <func,func,...> <out.c>`: decompiles named functions of a mod binary with Ghidra headless (`DecompileFunctions.java` is its script). The binary needs symbols (nitmod has them). Output convention: `decompile/<mod>_<version>/decompiled/<binary>_<topic>.c`, one `// ==== <name>` header per function.

Requirements: Ghidra and its JDK (Ghidra 11 and newer: JDK 21), found through `GHIDRA_HOME`, else the install folder of `ghidra` on `PATH`; runs outside the sandbox because Ghidra writes its settings to `~/.config/ghidra`.

## omnibot/, maps/

`omnibot/download.py`: downloads every ET file of the wolffiles.eu Bots category (omni-bot waypoints; advanced search `https://wolffiles.eu/search?category_id=12&game=ET`) into `omnibot/`; `maps/download.py` does the same for all ET maps (`category_id=10`, about 3100 files, roughly 45 GB) into `maps/`. Only the newest version of a file is fetched: the file name is read from the download redirect first, names that differ only in `_bN` or `_vN` tokens (decimals compared by number, `b` and `v` never against each other, a trailing `_waypoints` / `_waypoints_<n.n>` ignored) are versions of one file, and an older version already on disk is deleted once the newer one is there. Files keep the server's file name (`<slug>__` prefix if another file has that name); `index.tsv` (slug, file, status `downloaded`, `ignored <newer file>` or `removed` = deleted by hand) records every file, so a rerun only fetches new ones; a second run on the same folder exits while one is running; `--jobs N` parallel downloads (default 5). Needs network access to `wolffiles.eu` and its storage host.
