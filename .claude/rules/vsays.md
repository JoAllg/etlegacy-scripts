# Voice chat and vsays

Key layer mechanics (number row, `reset<Layer>`, popups): `.claude/rules/layers.md`. Vsay ids, variants and stock texts: `default/scripts/vsays/README.MD` (no need to open a pk3); command syntax: `docs/commands.md`, nitmod: `docs/commands_nitmod.md`.

| File | Status |
|---|---|
| `voicechat.cfg` | `v` opener, `resetVoiceChat`, execs `vsays/chat.cfg` and `vsays/vsays_custom.cfg` |
| `vsays/chat.cfg` | `chat<Category>` openers (exec the page), `cycleVsay<Name>` pointers, class vsays of the Function key (`vsay<Class>`, `cFun<Class>`) |
| `vsays/chat/*.cfg` | stock pages, exec'd when opened: `categories.cfg` (top; execs `serverconfigs/current_vsay.cfg`, which puts the entry page of the server the game is on on TAB), one per category, `<page>_shortcuts.cfg` (nitmod overrides) |
| `vsays/vsays_custom.cfg` | texts of the class vsays (`class/cs_classcripts.cfg`); live, not in version control |
| `vsays/chat_shortcuts.cfg` | nitmod only (exec'd by `mods/nitmod/mod_general.cfg`): redefines `chatRequests` / `chatGlobal` to exec `chat/<page>_shortcuts.cfg` after the page, which redefines some of its `vsay<key>` with `[S]`-style shortcuts. A text changed on a page may have its copy there |
| `vsays/servers/<clan>/*.cfg` | server voice chat pages; generated, not in version control, exec'd when opened |
| `vsays/chat_function.cfg` | not live (exec commented out in `chat.cfg`) |
| `vsays/vsaycolors.tsv` | record of `tools/vsaycolors.py` (colors of the last apply, reviewed texts): never edit |

- Server pages are generated by `tools/voicemenu.py <clan> <pk3> [address]` (the pk3 of the last run is named in the first line of each page; `<clan>` is the server id of `serverconfigs/servers.tsv`, `.claude/rules/serverconfigs.md`): edit only the vsay text in their `set vsay<key>` lines (a rerun keeps it per vsay and echoes it); everything else is rewritten from the server menu. Don't read the ~70 pages; one file (`servers/eg/eg_main_0.cfg`) shows the format.
- Page format (stock and server pages): `// Vsays` (`set vsay<key> "vsay <id> <text>"`, nothing else on the line), `// Echos` (`vstr popupsMenu`, heading, one `echo` per key), `// Binds` (`vstr unbindNumbers`, so no parent page action remains, then `bind <key> "vstr vsay<key>; vstr resetVoiceChat"`).
- All pages share the aliases `vsay1`..`vsay0` and redefine them when opened; never add an alias per vsay, key or echo: cvars are capped at `MAX_CVARS` (2048) and a hosted nitmod game crashes beyond it.
- A page restarts what it defines each time it is opened: a vsay that alternates between two texts has its steps on the page (`vsay<n>a` / `vsay<n>b`) and its pointer `cycleVsay<Name>` in `chat.cfg`.
- Colors: never pick color codes by hand. Texts use the `VSAY_*` colors and echo menus the `MENU_*` colors of `settings.conf`; write the text, then use the vsay-highlight skill (`tools/vsaycolors.py apply`).
- A vsay text is one chat line: at most 149 characters including color codes, no `;` or `"` inside.
- nitmod sends the text as a normal chat line and takes no variant number (`vsay <n> <id>` is legacy only).
