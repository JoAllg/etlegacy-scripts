# Voice chat and vsays

Key layer mechanics (number row, `resetLayers`, popups): `.claude/rules/layers.md`. Vsay ids, variants and stock texts: `default/scripts/vsays/README.MD` (no need to open a pk3); command syntax: `docs/commands.md`, nitmod: `docs/commands_nitmod.md`.

| File | Status |
|---|---|
| `voicechat.cfg` | `v` opener, execs `vsays/chat.cfg` and `vsays/vsays_custom.cfg` |
| `vsays/chat.cfg` | `chat<Category>` openers (exec the page), `cycleVsay<Name>` pointers, class vsays of the Function key (`vsay<Class>`, `cFun<Class>`) |
| `vsays/chat/*.cfg` | stock pages, exec'd when opened: `_menu.cfg` (top; execs `serverconfigs/current_vsay.cfg`, which puts the entry page of the server the game is on on TAB), one per category, `<page>_shortcuts.cfg` (nitmod and etps overrides) |
| `vsays/vsays_custom.cfg` | texts of the class vsays (`class/cs_classcripts.cfg`); live |
| `vsays/chat_shortcuts.cfg` | nitmod and etps (exec'd by their `mods/<mod>/mod_general.cfg`): redefines `chatRequests` / `chatGlobal` to exec `chat/<page>_shortcuts.cfg` after the page, which redefines some of its `vsay<key>` with `[S]`-style shortcuts, and redefines the syringe class vsay of `vsays_custom.cfg` with `[P]`. A text changed on a page or in `vsays_custom.cfg` may have its copy there |
| `serverconfigs/vsays/<clan>/*.cfg` | server voice chat pages; generated, not in version control, exec'd when opened |
| `serverconfigs/vsays/<clan>/shortcuts/<page>.cfg` | texts with chat shortcuts (`[H]`, `[P]`, ...) of the page's vsays (nitmod, etps servers only; vsay skill): `set vsay<key>` lines, exec'd by the page after its vsays; `voicemenu.py` keeps them per vsay and echoes them; not in version control |
| `serverconfigs/vsays/<clan>/override/*.cfg`, `serverconfigs/vsays/cycles.cfg` | server sounds on the stock pages (`<page>.cfg`) and class vsays (`<stock file>.cfg`) with the stock texts (hook `chatServer<Page>` of the openers, set in `<clan>.cfg`, reset in `default.cfg`) and their cycle pointers (`cycleServerVsay<Page>Key<key>`, `cycleServerVsay<Name>`; one per page and key, all servers; exec'd and so reset by `default.cfg`); written by the vsay-server-overrides skill, not in version control (`docs/serverconfigs.md`) |
| `vsays/servers` | versioned link to `serverconfigs/vsays/`, only for browsing: tools and exec paths use the real path |
| `vsays/chat_function.cfg` | not live (exec commented out in `chat.cfg`) |
| `serverconfigs/vsays/vsaycolors.tsv` | record of `tools/vsaycolors.py` (colors of the last apply, reviewed texts): never edit |

- Server pages are generated by `tools/voicemenu.py <clan> <pk3> [<pk3> ...] [--address host:port]` (several pk3s: menu and voice scripts in different ones; the pk3s of the last run are named in the first line of each page; `<clan>` is the server id of `serverconfigs/servers.tsv`, `.claude/rules/serverconfigs.md`): edit only the vsay text in their `set vsay<key>` lines (a rerun keeps it per vsay and echoes it) and the echoed item of a number key that sends no text (random vsay, page link) or the page heading behind the server tag (a rerun keeps both); everything else is rewritten from the server menu. Menu items on other keys than the number row are left out (a page binds its keys, a letter is a game bind), except a labelled link to a page ("N. Next"), which goes on a free number key; Back links are left out (CAPSLOCK goes up); vsays only reachable through left-out items go on the extra pages. Don't read the ~70 pages; one file (`serverconfigs/vsays/eg/eg_main_0.cfg`) shows the format.
- Page format (stock and server pages): `// Vsays` (`set vsay<key> "vsay <id> <text>"`, nothing else on the line; a server page with shortcut texts ends it with `execq` of its `shortcuts/<page>.cfg`), `// Echos` (`vstr popupsMenu`, heading, one `echo` per key), `// Binds` (`vstr unbindNumbers`, so no parent page action remains, then `bind <key> "vstr vsay<key>; vstr resetLayers"`, last `bind CAPSLOCK` to the parent page). Pages of a `TAB` chain cycle (the last one's `TAB` opens the first) and share the parent of the chain: `CAPSLOCK` goes there, not to the page before.
- All pages share the aliases `vsay1`..`vsay0` and redefine them when opened; never add an alias per vsay, key or echo: cvars are capped at `MAX_CVARS` (2048) and a hosted nitmod game crashes beyond it.
- A page restarts what it defines each time it is opened: a vsay that alternates between two texts has its steps on the page (`vsay<n>a` / `vsay<n>b`) and its pointer `cycleVsay<Name>` in `chat.cfg`.
- Colors: never pick color codes by hand. Vsay texts and chat texts (`say`, `say_team`, `say_teamnl`, `say_buddy`, anywhere in the profile: class report in `class/cs_output.cfg` and server cfgs, spawn lines of the autoexecs; not `say !command`) use the `VSAY_*` colors and echo menus the `MENU_*` colors of `settings.conf`; write the text, then use the vsay skill (`tools/vsaycolors.py apply`).
- A vsay text is one chat line: at most 149 characters including color codes, no `;` or `"` inside.
- nitmod sends the text as a normal chat line and takes no variant number (`vsay <n> <id>` is legacy only).
- Variant number: the text can't be quoted (a vsay sits inside a quoted alias, cfg quotes don't nest), so tools and skills read an all-digit first word after `vsay` / `vsay_team` as the variant number (`vsay <n> <id> <text>`); a vsay id is never all digits.
