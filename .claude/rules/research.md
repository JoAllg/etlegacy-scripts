# research/ (cvar and command dumps, location snapshots, decompiles)

Scripts are versioned, outputs are local (`.gitignore`). Tools, usage and requirements: `research/README.md`; local files (changelog, publishing risks, decompile index): `research/readme.local.md`. Dump workflow, column meanings and caveats: `research/dumps/README.md` (generated; read the section you need, 8 KB). Python tools follow `.claude/rules/tools.md`; they read paths from `settings.conf` only.

- Dump folders: `research/dumps/<mod>_<version>/` (`legacy_2.85.0`, `nitmod_2.3.5`, `jaymod_2.2.0`), legacy is the base of all diffs. Old folders stay; `build_docs.py` and `diff_profile.py` use the newest per mod.
- Generated, never edit by hand: `cvars.tsv`, `cmds.tsv`, `modules.tsv`, `diff_legacy.md`, `diff_profile.md`, `dumps/profile_unused.md` and `dumps/README.md` (its template is in `build_docs.py`). Regenerate: `research/dumps/dump_cvars.py [mod ...]` → `build_docs.py` → `diff_profile.py`; `dump_cvars.py --parse <dir>` re-parses a `console.log` (with its `modules.tsv`) without starting the game.
- `dump_cvars.py` finds the mods in `<fs_homepath>`, takes each mod's newest original pk3 (asks on the terminal if several match the newest version); legacy uses the pk3 of the 32-bit client's version (`<fs_basepath>/legacy/legacy_v<version>.pk3`, version from `GAME_BIN_I386 --version`; `fs_basepath` is read from the dedicated server next to that client, not `BASEPATH`). Every mod runs with `GAME_BIN_I386` (`GAME_BIN` with the x86_64 `qagame` if it is not set) so all dumps share one engine build, in a temporary `fs_homepath` with only that pk3 and the mod's `qagame.mp.i386.so` (no profile, no other pk3s), `+map fueldump`. It starts the game: needs the display, run it outside the sandbox. Mods without that module are skipped, a crashed run writes no data and the others continue; the final report lists dumped, skipped and failed mods with the game's error.
- `dump_cvars.py` (also `--parse`) and `diff_profile.py` need the ET: Legacy source: `ETLEGACY_SRC` in `settings.conf` (asked by `deploy.sh`) or the environment (checkout path: `CLAUDE.local.md`). They scan `src/**/*.c` for `Cvar_Get`/`Cvar_Set` to tell client from server engine cvars (`side`, `source` columns) and, in `profile_unused.md`, engine cvars a dump missed from names that do not exist. No checkout on this machine: clone it into the scratchpad for the run (`git clone --depth 1 https://github.com/etlegacy/etlegacy`), never into the repo; `build_docs.py` needs no source.
- `console.log` is 120–230 KB: never read it, `grep -n` for the line. The `.tsv` files are for `grep '^<name>	'` (columns `name, flags, value, default, side, source` / `name, description`), the `diff_*.md` files (15 KB) for `grep` too.
- `locations/locations.py` (driven by the `locations` skill): `extract` writes the snapshot `locations/maps_<YYYY-MM-DD>/` of the location files in the dlcache pk3s (`<pk3>__<file>` for a map pk3, `<pk3>/<file>` for a pack with several maps; `legacy_v*.pk3` skipped; a rerun the same day rebuilds that day's folder) and `locations/report_<YYYY-MM-DD>.txt` (new and changed files against the newest older snapshot, snapshot maps without a file in `<profile>/maps/`; a processed report ends with a `handled <date>` line). `diff`, `add`, `merge`, `caps` bring the files into `default/maps/` (dry run without `--apply`). Rerun after new downloads.
- `changelog_2.84-2.86.md` (19 KB): legacy changes per version, grep by cvar or keyword.
- Decompiles of closed mods: `research/decompile/<mod>_<version>/decompiled/<binary>_<topic>.c`, made with `research/decompile/decompile.sh <binary> <func,func,...> <out.c>` (Ghidra headless, `GHIDRA_HOME`). Grep the existing files (`readme.local.md` lists them) before decompiling again, and add new functions there, never in the scratchpad. The files are 10–340 KB: grep for the function (`// ==== <name>`) and read only that part.
- A fact taken from a dump or decompile is cited in docs with its source (`research/decompile/<mod>_<version>/decompiled/<file>.c`), and marked "not tested in game" until the user confirmed it.
